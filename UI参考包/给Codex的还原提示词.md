# 给 Codex 的界面还原提示词

请根据当前项目中的微信小程序代码和 `UI参考包`，把现有界面调整为参考图所示的视觉风格，并保持现有业务流程可用。

## 参考资料

- 先逐张查看 `界面原图裁切/` 中 01–10 的原始界面截图。这些截图是最终视觉参考，尤其是启动页的云海宠物插画、首页卡片布局、对话气泡、星图的深色背景、我的页面设置列表和封存弹窗。
- 再查看 `SVG可编辑参考/` 中对应编号的 SVG，用于理解页面结构、文字层级、卡片位置和大致间距。SVG 是可编辑的近似重绘稿，插画和个别图标为简化示意；不要把 SVG 里的简笔宠物头像当作最终插画风格。
- 截图裁切文件放大后便于查看，但没有增加原始图片的像素细节。若要调整比例，优先保留布局关系、色彩气质和留白。

## 开始实现前

1. 检查项目结构、路由、页面现有实现和已连接的 DeepSeek / 数据库逻辑。
2. 找到现有小程序页面并原地改造；不要另建一套与现有入口无关的静态演示页面。
3. 保留现有数据字段、核心交互、隐私约束和已经可用的后端连接。不要把 API 密钥写进小程序前端。
4. 按页面逐一落实并检查页面滚动、底部安全区、按钮可点区域和文字可读性。

## 页面清单

1. 启动页：云蓝天空渐变、细小星光、暖色云海，猫狗从背后并肩望向天光；中上部展示“云间小窝”“云间有小窝，思念有归处”“在这里，你可以慢慢说想念。”；底部为圆角“进入小窝”按钮。
2. 首页：简短问候；两列圆角入口卡片，依次包含云窝档案、悄悄话信箱、云间来信、同念星图、云伴小栈；下方“我的”入口；底部首页 / 消息 / 我的导航。
3. 云窝档案：宠物头像、名字与基本信息、性格标签、小习惯、专属小故事、多图区域和编辑按钮。保持内容分组清楚、卡片留白充足。
4. 悄悄话信箱：宠物头像与消息气泡，主人消息使用浅雾蓝气泡，时间戳弱化显示，底部固定输入框和发送按钮。
5. 云间来信：柔和天空与云层插画，日期、来信卡片、宠物署名、“再来一封”按钮和每日来信开关。
6. 同念星图：深蓝星空、柔和发光星点、城市标签和一条匿名思念卡；不展示头像、昵称，不提供私聊或好友入口。
7. 云伴小栈：按离世时间分组的筛选胶囊、匿名文字卡片和发布入口；不要添加点赞、评论回复、@或私聊。
8. 我的页面：宠物档案和封存档案入口；设置列表包含云间来信、同念星图、云伴小栈、独处安静模式和消息推送；独处模式开启后只保留档案与悄悄话信箱。
9. 封存确认：半透明暗色遮罩、居中圆角弹窗、温和说明、取消与封存两个按钮。明确封存不是删除，档案、照片和对话永久保留。
10. 云窗：展示组件样式 A（宠物照片 + 最新来信）与样式 B（星光爪印 + slogan）的视觉方案。MVP 中提供小程序内的组件预览/配置；系统桌面小组件能力按微信平台实际支持情况实现，不要伪称已安装到桌面。

## 样式要求

- 使用奶白、浅灰、淡雾蓝、浅燕麦、柔和杏色；避免刺眼高饱和色和强烈黑色描边。
- 页面视觉要细腻、轻盈、舒展。卡片圆角和留白统一；字体层级明显但不过粗；插画优先使用细腻、温暖、具有体积感的云层和动物图，不要使用空白圆头或几何占位宠物作为最终图。
- 动画节奏缓慢，使用淡入淡出、星点轻微呼吸；不要做弹跳动画。
- 输入框保持简洁；图片预览圆角；弹窗可使用低透明度叠层和柔和阴影。
- 适配微信小程序尺寸与安全区域，滚动内容不能被底部导航遮挡。

## 不可违反的产品边界

- 页面需要明确这是思念记录与 AI 陪伴，不是宠物复活，无法真正与宠物沟通；不得承诺重逢。
- 不新增点赞、收藏、排行榜、热度、私聊、好友、关注或引流功能。
- 星图只允许用户自愿展示城市和一句匿名短句；位置权限可跳过，禁止强制获取精确经纬度。
- 圈子匿名，允许退出；不提供评论回复层级。
- 封存只暂停每日来信，不删除档案、照片和对话。
- 若用户内容呈现持续强烈自伤风险，温和提示寻求可信任的人和专业援助，不以宠物口吻承担危机干预。

## 完成标准

- 按现有项目实现并接好页面跳转，不用静态图覆盖整个可交互页面。
- 保留当前可运行流程和数据逻辑；不将示例内容误当成真实用户数据。
- 完成后列出修改文件、尚未接入的系统能力和需要在微信开发者工具中确认的步骤。
